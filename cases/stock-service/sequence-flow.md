# Диаграмма последовательности

Диаграмма показывает два логических процесса отдельно: обновление данных и чтение остатков клиентским приложением. Она не задаёт периодичность обновления, гарантии доставки или точную реализацию интеграционного потребителя.

## 1. Обновление данных

```mermaid
sequenceDiagram
    participant ERP as Учётная система
    participant HUB as Интеграционная платформа
    participant K as Kafka
    participant S as Сервис представления остатков
    participant DB as База данных сервиса

    ERP->>HUB: Передать данные об остатках
    HUB->>K: Опубликовать данные в интеграционном потоке
    K-->>S: Доставить сообщение
    S->>DB: Сохранить/обновить данные
    DB-->>S: Подтвердить результат операции
```

## 2. Получение остатков

```mermaid
sequenceDiagram
    participant C as Клиентское приложение
    participant S as Сервис представления остатков
    participant DB as База данных сервиса

    C->>S: Запрос остатков через API
    S->>S: Проверить параметры и выполнить бизнес-логику
    S->>DB: Получить данные
    DB-->>S: Вернуть найденные данные
    S-->>C: Ответ API
```

## Примечания

- Это логическая последовательность, а не спецификация протоколов.
- Не показаны не подтверждённые детали: конкретные коды ответа, повторы, дедупликация, DLQ и транзакционные границы.
- Ошибочные и альтернативные сценарии следует добавлять после сверки с фактическими требованиями и реализацией.
